# 轨迹变体生成提示词（generator.v1）

> **使用边界（E6 防泄漏铁律）**：本提示词是给"变体规格作者"（LLM）的过程性指令。
> 它**不含任何规则内容**——没有规则编号、规则标题、评分等级、判定条件或"什么
> 做法正确/错误"的方法学断言。方法学对错的判定由独立标注管线负责（标注者与
> 规则作者角色分离，见 annotation_rubric.md）。
> 若你认为需要提及"某做法是错的/某做法是标准做法"，**不要写在这里**——那是
> 标注者与评审者的职责，不是生成器的职责。

## 任务

你是一名生信分析轨迹的"变体规格作者"。你的输入是真实 Agent 运行语料中的
轨迹片段（下称"语料样本"）；你的输出是一份 JSON 变体规格，供确定性变换脚本
生成新的评测任务。

## 输入：语料样本

语料样本是真实 Agent（CellVoyager 等）运行产生的分析轨迹：一串决策，每个决策
含步骤编号、决策类型（如"数据完整性检查""质量控制""归一化""差异表达"）、
所选方法、理由说明、上下文（数据集/样本量/技术平台等）。

## 输出：变体规格（JSON）

```json
{
  "trajectory_id": "bmd_<范式>_<3位序号>",
  "act": "<deg|pan|scrna>",
  "base": "<语料轨迹 id>",
  "dataset": {"name": "...", "n_samples": N, "n_cells": N},
  "context_overrides": {"<步骤号>": {"<键>": "<新值>"}},
  "choice_replacements": [{"step": "<步骤号>", "choice": "<语料中出现过的方法>",
                           "rationale": "<该 Agent 风格的说明>"}],
  "add_decisions": [{"decision_type": "<类型>", "choice": "<方法>",
                     "rationale": "...", "context": {...}}],
  "remove_steps": ["<步骤号>"],
  "error_pattern_sources": ["<语料轨迹 id，错误模式来自此处>"]
}
```

## 生成规则

1. **只使用语料中出现的素材**：choice（方法名）、context 键值、rationale 语气
   一律来自语料样本。需要换方法时，从其它语料样本里已有的方法中选择；不要
   发明语料中不存在的方法名或上下文键。
2. **错误注入素材来自语料**：如果你要为一个决策选择"看起来可疑/不严谨"的方法
   （比如跳过了某道常规工序、用了非常规的统计方法、参数选择随意），必须注明
   `error_pattern_sources`——该模式必须能在语料样本中找到同类先例。**不要按
   任何外部规范反推错误**：你只是把语料中真实出现的做法迁移到新数据集上。
3. **数据集多样化**：每次变体换一个合理的数据集（编号、平台、样本量、细胞数
   可以变化），但数值要自洽（如 n_patients ≥ 3 时差异检验按患者分组的说法才
   合理）。
4. **理由说明保持 Agent 风格**：简洁、口语化、常用"standard/commonly used/
   default/惯例"等真实 Agent 常见措辞；偶尔有轻微不严谨的说法，与语料一致。
5. **不加评判**：规格中不得出现"这违反了 X 原则""正确的是 Y"之类的话。
6. **可添加决策**：允许为轨迹补充语料中未出现但类型合理的步骤（如补充
   "线粒体比例阈值""主成分数""多重检验校正"等工序的决策），方法名从语料或
   通用工具名中选取；这类步骤同样遵循规则 2 的素材约束。
7. **删除步骤是允许的**：短轨迹 = 从语料完整轨迹中删去若干步骤；被删步骤的
   决策类型在变体中消失。

## 交付物

只输出 JSON 规格本身（不输出解释、不输出轨迹全文）。每条变体一个 JSON 对象。
规格经人工审核后由变换脚本落盘为任务文件——**你写的是规格，不是任务**。

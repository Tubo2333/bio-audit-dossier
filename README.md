# bio-audit-dossier

**一份可随稿件或数据集交付的、有界的决策级审计记录。**

本仓库提供 Bio-Audit 体系的**审计交付面**：接收一次命名分析的方法学决策声明与执行观察，逐点给出判定、依据、限制与停止条件，并产出可归档的交付件。**本系统不对分析给出评分、排名或科学正确性结论。**

所属体系：[bio-audit](https://github.com/Tubo2333/bio-audit)（审计引擎、规则库、评测集与演示台）。

---

## 1. 本仓库解决什么问题

自动化分析流程在方法学层面可能出现三类问题，且均不伴随运行错误：

- **声明与实际执行不一致**——提交方声明采用某方法，执行记录中无对应操作；
- **预期决策点缺失**——该平台与范式下的标准流程应包含的决策，未被执行亦未被声明；
- **方法选择与上下文不适配**——方法与所选阈值、样本规则或数据结构不相容，导致结论支持力被高估。

上述问题无法通过代码审查或结果核对发现，须对照领域方法学共识逐决策核验。本系统将该核验过程结构化，并使其结果可交付、可追溯、可复算。

## 2. 审计对象与范围

被审对象为**一次命名的 bulk RNA-seq 差异表达分析**，包含下列五个决策点：

| 编号 | 决策点 | 该点回答的问题 |
|---|---|---|
| DP-01 | 低表达基因过滤 | 是否执行过滤、依据何种阈值、证据支持至何程度 |
| DP-02 | 标准化方法 | 所选方法与当前分析背景的适配性及其证据 |
| DP-03 | 差异分析方法 | 方法选择与统计问题、数据结构的相关性 |
| DP-04 | 多重检验校正 | 校正方法、其证据与限制 |
| DP-05 | 显著性与效应量阈值 | 阈值的解释力边界（不构成因果或生物学重要性判断） |

五个决策点相互独立、不得合并，亦不得以任一点的证据补足另一点的缺口。

**本版未覆盖**：其他分析类型（单细胞、泛癌、DEG 等）、更多决策点、分析级结构化结果的对外呈现、复核与历史变更的完整呈现、运行时证明、部署与包级闭包。上述各项均为排期与授权边界，而非能力删除；其位置在体系中予以保留（见 §7）。

## 3. 判定模型

系统对每个决策点输出**分类判定**，而非数值评分。三类失败在语义上严格分离：

| 判定 | 含义 | 系统行为 |
|---|---|---|
| **auditable** | 关键事实、上下文与证据可确认 | 给出该点的支持范围与限制 |
| **scientifically inadequate** | 事实基本清楚，但方法或证据仅支持较弱结论 | 保留可支持部分，显式声明限制 |
| **not auditable** | 关键事实、上下文或证据无法确认 | 停止受影响判定及其下游结论；不以默认值、相似项目或历史记录补齐 |
| **integrity / authority failure** | 身份、版本、来源、绑定、快照、权限或唯一权威关系失败 | 隔离受影响材料，保留待裁决事项；不降格为普通科学不足 |

**证据的来源与验证状态分别记录、不得混同**：

- 来源类型：`declared`（提交方声明）· `observed`（脚本、日志、参数、产物）· `referenced`（规则、文献、协议）· `derived`（系统推导）
- 验证状态：`confirmed` · `unverified` · `conflicted` · `not_applicable`

硬性约束：`declared` 不等于 `confirmed`；`derived` 不等于 `observed`；规则或文献不等于实际执行事实。无执行观察时，审计仅达**声明级**，不得声称执行已获确认。

## 4. 输入

提交须包含四层内容：

1. **分析上下文**——项目标识、分析标识、比较对象、数据类型与范式、审计范围、预期用途；
2. **决策声明**——五个决策点各自的方法、阈值、样本规则、作用单位及其声明来源；
3. **证据与观察**——声明、脚本参数、日志、笔记本、实际产物、规则与文献依据（各项保留来源类型与验证状态）；
4. **修正关系**——若为重审，引用既有审计记录并说明变更内容。

**完整性七域**须逐域合格：`identity` · `version` · `source` · `binding` · `snapshot` · `permission` · `unique_authority`。任域不合格的后果为**逐点** `not_auditable`；批次层仅校验类型与形状（顶层结构 + 决策点键集恰为五项），缺决策点即为**批次级拒绝**，不写入任何记录。

## 5. 输出

每次审计产出三项：

| 产物 | 说明 |
|---|---|
| `report.json` | 结构化审计记录 |
| `report.html` | 检查页：供对分析负责者自行核查，含三档阅读深度（结论 / 理由 / 证据链）与判据面板 |
| `deliverable.html` | 交付件：单文件 HTML，含打印样式，可随稿件或数据集归档 |

交付件受八条硬性约束：不得成为第二权威；不得将四个轴合成为单一评分；限制与停止后果不得省略；使用上限须照录审计记录所载，不得因形制正式而提高；不得出现「通过 / 合格 / 可信 / 已验证」类结论词；须附生成时刻与所渲染记录的快照引用；须声明中文层为渲染层翻译而非权威表述；不得替代验收、发布或包级闭包的任何主张。

## 6. 受控的下一步动作

系统仅输出下列四类动作，且各自附带相应非声称：

| 动作 | 含义 | 非声称 |
|---|---|---|
| `request_evidence` | 补充指定证据 | ≠ 证据已被接受 |
| `submit_correction` | 提交新的分析或决策版本 | ≠ 修正已生效 |
| `request_review` | 请求科学或治理复核 | ≠ 复核方已批准 |
| `stop` | 停止或放弃本轮 | ≠ 历史记录已删除 |

补证据或提交修正**不覆盖**原记录：系统建立新的完整输入快照与新的审计尝试，并保留新旧记录之间的关联。

## 7. 与体系其余部分的关系

本仓库复用 [bio-audit](https://github.com/Tubo2333/bio-audit) 的引擎、规则库与决策本体，但**审计记录不消费该引擎的聚合分数、等级、评测分或训练信号**；上述数值仅保留在内部诊断与回归层。

| | bio-audit（父仓库） | 本仓库 |
|---|---|---|
| 面向 | 引擎、规则库、评测集、演示台 | 审计交付面、判据链、交付件、提交面 |
| 输出 | 轨迹评分、verdict、维度分、benchmark、reward | 分类判定、依据、限制、使用上限、受控动作 |
| 口径 | 可量化，供评测与回归使用 | 不可量化，仅供有界使用 |

**两个仓库的数值口径不得混写**：父仓库的分数不构成本仓库的结论，本仓库的判定亦不构成父仓库的评分。

本仓库另含四页交互式演示台（`demo/`），用于呈现引擎与评测层的运行方式。**该演示台所述分数与 benchmark 属于父仓库口径，不属于本仓库审计记录的内容。**

## 8. 快速开始

```bash
pip install -e ".[dev,a1]"       # 需要 Python >= 3.10；a1 附加项为网页提交表单所需

# 提交一次分析并产出三项交付物（默认写入 var/）
python scripts/submit_analysis.py --file <submission.json>

# 生成一份完整的示例提交（含反例，用于核验 fail-closed 行为）
python scripts/make_example_submission.py --out-dir _tmp_a1

# 网页提交表单（本地服务，默认端口 5050）
python ui/a1_submit_app.py --port 5050
```

Windows 环境可双击 `start-a1-web.bat` 启动提交表单，双击 `启动演示.bat` 启动四页演示台。

## 9. 工程的核验方式

```bash
python -m pytest -q                     # 全量测试
python ui/verify_report.py              # 检查页产物级断言（19 项）
python ui/verify_deliverable.py         # 交付件产物级断言（10 项）
python scripts/check_rule_lifecycle.py  # 规则库生命周期（清单一致 / 副本一致 / 占位自述 / 重看窗口）
```

规则库中每条规则均附文献依据，依据的持久标识符经逐条核验；规则库的生命周期检查已接入持续集成。

## 10. 边界声明

- 本系统**不**给出分析评分、排名、质量总分或置信度；
- 本系统**不**判定科学正确性，亦不替代统计学家、复核方或领域专家的判断；
- 本系统的判定仅在其所声明的项目、分析与审计范围之内成立；
- 交付件是某一时刻的**渲染快照**，不产生新结论、不授予新授权；
- 中文为渲染层翻译，非权威表述。
